# 全部议题的旅程原话复查

N6组装和N7交付前都按“议题×步骤”逐项检查，不能只修第一个议题/第一步。先列出所有stage，读取已有引用与上下文，再在已取得的同产品材料里找直接原话。原话只谈相近需求或障碍时可引用，但须说明它与这一步的共同点以及没有证明什么；仅有同类词汇、竞品问题、文件违规申诉与账号恢复等不同对象不能混用。

每条摘录均为真实正文的逐字子串并有可回查ID/来源。`quote_matches`记录{evidence_id,anchor,match_type:direct/semantic_similar,match_reason}；semantic_similar必须有完整匹配理由。`feeling_basis`引用同一来源时关系必须一致。网页在原话后仅显示“语义相近”小标签、日期、来源和原文入口。完整匹配理由保留在quote_matches/feeling_basis和研究审计中，不在每张卡上显示长段灰色解释。

对每个步骤先阅读原话及上下文，充分时直接判断并填写具体feeling_label和对应feeling_basis，不把已有依据的步骤留作“感受待判”。相近原文可以支撑需求，却未必支撑该阶段的感受。没有阶段感受依据仍留feeling=null；不把期待当已体验、担心当已丢失、要求申诉入口当已经申诉失败。曲线保持连接，缺证位置是导线而非评分。原文跨PC/iOS、历史或条件待核时保留条件；用于旅程说明不增加合格评论数，同一评论多处引用不增加人数。

有直接引用的步骤保留直接依据，不为装满图而强加“相近”。找不到相关材料则写`quote_gap_reason`，说明已查的范围和缺少什么；平台筛选后没有原话也如实显示。生成后逐项看`check-report.json > structural_checks.journey_quote_coverage.rows`，每一步都应有来源，或有具体缺口；missing_review应为0。再实际打开全部议题，检查简短标签、原文入口、连续曲线和平台筛选，并在结构化数据中复查理由。校验器检查结构与逐字锚点，不替代匹配语义的人工/Agent复查。
