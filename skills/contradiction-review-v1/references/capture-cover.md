# 页首真实产品界面图（每次必做）

按与研究功能的相关性和画面可读性选图，不把官网或App Store规定为唯一入口。允许本次打开App后的真实截图、用户公开分享的功能使用截图、新闻/测评中的产品界面截图，以及官网、应用商店的真实展示图。优先看到真实功能使用场景，而非只截产品名称和评分。不要生成或自画UI，也不能用其他App、登录验证页、报错页或纯文字观点卡替代。

先查看原页面/图片，确认是目标产品、可辨识的功能界面。记录原发布者、原文链接、素材时间、客户端/版本（不明则写不明）。历史或PC/iOS配图可作产品识别，但需在图注写明，不冒充当前安卓实机测试。用户截图中的私人文件、账号不得照搬；选不含私人信息的公开示例或在拍摄前隐藏。不要为了配图改写截图中的状态。

`hero.image`字段：
- `kind`：app_screenshot / website_screenshot / official_image / user_screenshot / report_screenshot。
- `data`：本次实际取得的JPEG或PNG base64，最大2MB；不用ImageGen。
- `source_url`：原帖、原报道或最终产品页的可回查链接；可另存`media_url`记录图片文件来源。
- `author`：实际发布者/报道来源，不能把他人截图写成“本次实测”。
- `captured_at`：含时区的本次截图/取得时间；旧图不因此变成新图。`sha256`为嵌入图片字节的SHA-256。
- `alt`、`caption`：说明产品、功能场景、素材日期、客户端。公开报道截图写“报道配图”，用户截图写“用户分享界面”；不是本次操作就不能写本次实测。
- `usage_note`：说明仅用于产品/场景识别，还是本次观察了哪些操作；不得把配图当成效果验证。版权归原权利人，不虚构CC或开放许可；确有许可才填`license`和`license_url`。

获取失败可换其他上述公开来源；仍不可得则保留截图缺口。capture.json保留原链接、素材时间、本次取得时间、方式、客户端和哈希。浏览器资料、Cookie或私有请求头不入交付包。

## 多张竖版图与封面尺寸

首页外部布局和图片区底框的宽、高、位置、圆角、边框、间距按已确认模板锁定，只能替换框内内容。横图在既定图片槽内保持原比例完整显示并水平/垂直居中；竖图选择两张相关真实产品图在同一槽内左右并排，各自保持比例、居中、完整显示；优先选相同竖版比例。不要改为随原图自然高度撑开的外框。hero.image继续保留主图以兼容旧输入；hero.gallery_caption可给整组说明。每张images元素都必须包含与主图相同的来源、时间、哈希、作者和使用说明；不同来源均保留署名链接。可记录真实width/height，不能编造尺寸或将历史/其他客户端素材写成本次安卓实测。

保持原有左文右图、标题字号和图片区宽度。不得以播放动画、三页停靠或一屏装满为由把图片固定缩成小图、缩小整页或裁掉真实界面；按[交互呈现规范](interaction-presentation.md)处理短窗口阅读。

本规则优先于旧版“2—4张”或按原图高度自适应建议；见[布局锁定与验收](cover-layout-lock.md)。
