# 范围、入池与计数

## 输入范围

一次输入目标App与可选重点。默认单App、国内安卓手机端、近12个月；近90天单列。iOS、鸿蒙、Windows、macOS、网页端与版本不明材料分别标记，不能直接计作安卓当前版本证据。版本、付费条件和使用场景允许unknown；未知是待核条件，不是任意适用。

固定基础为应用宝；核心社媒为小红书、微博、知乎。B站保留，抖音本轮已授权启用；知乎待本地接入实测。即刻、豆瓣按议题定向补证，脉脉用于匹配的职场/行业研究。V2EX、小众软件论坛定向补证，官方帮助/更新记录核对功能与版本。核心来源受限时报告缺口，既有缓存导入不称重新采集，接入不称实测通过。详见[来源计划](source-plan.md)。

## 语义初筛标签

| code | 可取的含义 | 数量用途 |
|---|---|---|
| P | 目标App的具体问题、明确改动/新增/恢复诉求 | 研究池；问题/诉求数单列 |
| V | 有明确功能或设计对象的价值评价、偏好或取舍 | 研究池；不全算待修复问题 |
| C | 用法答疑、替代工具、机制解释、转述、简单附和、未使用预期 | 辅助背景；不计独立需求 |
| U | 缺父回复/图片/视频、指代不清、无法可靠归于目标App | 待补证；不计有效目标 |
| G | 泛泛好坏评、歌词与梗、闲聊、交易、推广，无可定位功能内容 | 保留审计记录；不计有效目标 |
| E | 明确事件/抵制/评分表态，且没有可分离功能内容 | 事件背景；不计有效目标 |

例：日推始终重复同一批歌、关闭自动续费入口找不到 → P；日推能发现喜欢的新歌、希望保留一起听 → V；下载哪个版本、谢谢/+1、售卖皮肤 → C或G；“我也是这样”且关键截图未取得 → U。

标签由模型逐条理解或人工标注。脚本只校验、路由与计数，不是语义模型。P优先于V：混合评论有具体问题就保留该片段；情绪、星级、事件信号与功能信息分别判断。已有上下文中明确自述同一故障，可以引用父级证据；仅赞同不能自动变成独立经历。引用别人的问题不归到本条作者。

截图依赖仅影响依赖截图的主张；文字已经明确描述的问题可作为未核实自述保留，但不能升级为图像核验完成。不得把App商店评论框限制、第三方下载站故障或竞品问题误归给目标App。

## 当前分析的门槛

研究池P+V与当前范围内有效数分开。当前范围有效记录需要：目标App匹配、原文可追溯、语义有依据、关键上下文充足、发布时间在选定窗口、客户端匹配。未知客户端/日期进入待核队列，不默认为安卓/近期。当前版本适用性仍需结合版本或官方资料核对；时间和数量通过并不完成这一判断。

数值口径：原始评论ID → 非空非纯符号 → 同文去重 → P/V初筛 → 时间/客户端等范围核验。拆出多个主张不增加评论数；跨站同文只计一次，不把同文直接认定为同一个人。作者不可得时人数未知。同一作者同一话题的追问、澄清与修复结果应关联，不作为额外支持票。

当前目标：至少1000条语义筛后、去重且符合选定范围的研究反馈P+V；同时单列P，不能用V冒充1000条改动诉求。需要更严格的“1000条明确问题”时使用P门槛。历史与日期不明材料不补足近期缺口。人未复核就标注AI初筛，不宣称已验证准确率。

议题级主收藏榜沿用100条合格去重相关反馈门槛；议题对象与相关性还需模型/人工核对。不到100的具体缺陷进入观察区，严重问题单列影响，不伪装成熟主榜议题。100不是100个人、总体多数或统计显著性。

## 冲突判定

可以判为冲突候选：同一决策对象、相关条件可比，并有可追溯的相斥要求。不可直接判为冲突：

- 一条要求功能正常，另一条要求删除功能；未核对前不能配对。
- 不同客户端或版本的差异。
- 一个要可选功能，另一个反对默认展示；先检查是否能共存。
- 只有一方、只有泛评、或缺少关键上下文。

相反情绪不等于相反诉求。允许输出单侧问题、条件差异、可兼容偏好与证据不足，不为图表凑正反方。

## 采集预算

技术准备门槛与研究数量门槛分开。先检查已有collector的登录复用、分页、正文及上下文状态，访问拒绝时停止该路径，不为凑量绕过限制。

原始预算约为目标有效数÷实测有效率。分别按来源、时间和主题观察，每新增约500条重算有效率与重复率；该分批数是工作约定，可按访问情况缩小。当前网易云样本近12个月P+V为119/402，P为104/402；这是选定帖子混合下的初筛率，不能保证下一批相同。5000—6500条近期相关评论仅为考虑后续损失的预算建议，不是授权、库存保证或硬性采集量。

数量不足时交付已取得证据与缺口；不得放宽语义标准、扩大历史窗口或加入交易闲聊来凑数。

## 可执行范围校验

`python3 scripts/research_gate.py references/research_gate.example.json --output <结果路径> --collection-gate <技术门槛JSON>`。
示例是合成输入，不是实采；`--collection-gate`可省略，省略时技术准备状态保持未检查。

输入根字段为scope与records。scope要求app、带时区的start/end；client默认android，可选android / ios / harmonyos / windows / macos / web / all。all仅用于明确选择的跨客户端研究，不代表安卓已核验。version可省略或给具体版本；payment为all / free / paid；issue_ids可限定已经标注的议题。target_effective默认1000，target_kind为research_feedback（P+V）或problem_request（P）。

每条记录需要evidence_id、body、code、app、source_platform、client、published_at与source_url或source_file。P/V要有原文中的anchor，basis为self_report或direct_preference，context_dependency为none或resolved，review_status为model_first_pass或human_reviewed。hearsay / explicit_nonuse / unknown依据单列背景/待核；客户端、版本、支付状态、上下文与日期的unknown不能补成匹配。

程序不会从星级、关键词或型号猜语义、安卓归属、恶意动机，也不会核定用户所述故障真实。AI初筛的数值通过仍不通过人工Gate、当前版本适用性判断或真正冲突判定。
